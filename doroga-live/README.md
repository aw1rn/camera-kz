# Дорога Live — сайт для просмотра дорожных камер

Статический сайт для GitHub Pages: 6 примеров камер KazToll, поиск по ним, собственная ссылка на HTTPS MP4, автообновление фрагмента каждые 12 секунд, яркость/контраст/насыщенность и простая резкость, сравнение с оригиналом, полный экран. Обработка изображения выполняется на устройстве пользователя. Это не официальный сайт KazToll.

## Как разместить на GitHub Pages

1. Создайте репозиторий на GitHub.
2. Добавьте файлы `index.html`, `style.css`, `app.js` и этот README в **корень** репозитория (не помещайте их в дополнительную папку).
3. В репозитории откройте Settings → Pages.
4. В разделе Build and deployment выберите Deploy from a branch, ветку `main`, папку `/ (root)` и нажмите Save.
5. Дождитесь публикации и откройте адрес, который покажет GitHub Pages. Сайт работает по HTTPS и не требует собственного сервера для своей оболочки.

## Если браузер не открывает H.265: локальное перекодирование

В комплекте есть необязательный локальный адаптер: он скачивает последние фрагменты шести встроенных камер и перекодирует их в H.264 с помощью FFmpeg. Установите Python 3 и FFmpeg (должен быть доступен в PATH), затем в папке проекта выполните:

```bash
python local_server.py
```

Откройте `http://127.0.0.1:8765/?local=1`. Программа работает только на вашем компьютере. Первое подключение может занимать значительное время; скорость и задержка зависят от процессора и сети. Этот адаптер не обрабатывает произвольные пользовательские URL. Остановить его можно через Ctrl+C. GitHub Pages не запускает Python, поэтому при публикации этот локальный режим не заработает на GitHub без отдельного сервера.

## Что важно про потоки

При проверке фрагмент `cam1.mp4` оказался видео в кодеке **HEVC / H.265**. Не каждый браузер или устройство воспроизводит этот кодек. В тестовом Chromium видео не воспроизвелось; GitHub Pages не умеет перекодировать видео. Если в вашем браузере тоже не работает, требуется отдельный сервер перекодирования в H.264 или поток в H.264 от источника.

- Адреса камер и схема обновляемых MP4 предоставлены заказчиком. Актуальность и CORS в конечной сети пользователя не гарантированы. Потоки загружаются напрямую с KazToll: доступность и права использования нужно проверить у владельца источника. Если сервер отключил CORS, доступ, или адрес изменился, браузер может не показать поток.
- Это короткие перезаписываемые клипы, а не истинное видео в реальном времени; при обновлении возможны задержки и разрывы. Данные из старого фрагмента не следует считать текущими.
- На статическом GitHub Pages нет серверного API, каталога всех 128 камер, автосинхронизации и RTSP/Range-прокси; перечислены только 6 предоставленных примеров. Прокси и RTSP-потоки требуют отдельного сервера.
- Для пользовательских ссылок поддерживается только HTTPS; сюда нельзя вставлять приватные ссылки, логины, пароли или токены — адрес уйдёт в браузер при запросе к выбранному источнику. Страница не передает ссылки на дополнительный сервер приложения.
- Фильтры регулируют яркость, контраст и насыщенность. Резкость — простая обработка краёв, а не нейросеть и не настоящее восстановление потерянных деталей. Она может создавать артефакты. Не используйте обработанную картинку как доказательство или единственный источник для решений о безопасности.
- Если браузер не может обработать кадры из-за CORS, видео может быть недоступно; при удачном воспроизведении без разрешения читать пиксели резкость отключается, и показывается видеопоток с базовыми CSS-фильтрами. Интенсивная обработка зависит от мощности устройства.
